# backend/realtime

루트 문서를 먼저 읽는다: `/CLAUDE.md`, `backend/CLAUDE.md`(백엔드 공통), `docs/events.md`(정본), `docs/data-model.md`(`event_log`).

## 책임

- SSE 엔드포인트 2개(전체/개인) 구현
- `event_log` 채번(`seq`)·발행, 재연결 시 `Last-Event-ID` 기반 재전송
- 다른 모듈이 이벤트를 발행할 수 있는 공통 인터페이스 제공 (`publish(map_id, channel, type, payload)`)

## 하지 않는 것

- 이벤트의 발생 트리거 자체는 이 모듈이 결정하지 않는다. "핀이 게시되면 `pin.published`를 보낸다"는 `pins`/`recommend` 모듈이 이 모듈의 `publish()`를 호출하는 방식으로 구현한다.

## 넘지 말 것

- **전체 채널과 개인 채널을 코드 레벨에서 분리한다.** 개인 채널 이벤트가 실수로 전체 채널로 새면 가드레일 1(AI는 지도를 바꾸지 않는다 — 공개 범위를 사람이 결정)이 깨진다. 이 부분은 반드시 테스트로 고정한다.
- `docs/events.md`에 없는 이벤트 타입을 임의로 추가하지 않는다 — 추가되면 루트가 문서에 반영.

## 완료 정의

- SSE 두 채널 구현 + 단위 테스트
- **개인 채널 이벤트가 전체 채널 구독자에게 절대 도달하지 않는다**는 테스트 (가장 중요한 테스트)
- 재연결 시 `Last-Event-ID` 이후 이벤트만 재전송되는지 테스트
