### 발견 (추천 품질)
- **F-1 안전 사유가 키 없는 줄로만 남음(알레르기)**: 모델이 `fact_key` 없는 `required` 줄을 만들 뿐 후보에는 어떤 경고도 붙지 않는다(결과 응답에 고지 필드도 없음). 설계상 알레르기는 걸러 주지 않고 FE가 고지를 띄우는 것(demo-guide #425)인데, **UI에서 실제로 고지가 뜨는지 UI 단계에서 확인 필요**. (인젝션 문구도 같은 경로)
- **F-3 과잉 추출**: "양식은 느끼해서 싫어요" → `cuisine_western` + `oily_focused`(기름진 메뉴 위주) 두 개의 실격 조건. 이유(느끼해서)를 별도 실격으로 만들어 카드에 「기름진 메뉴 위주 확인 필요?」 잡음이 생긴다. 모델 프롬프트 튜닝 후보.
- **F-4 충족 집계 vs 보이는 체크 불일치**: 보이는 체크가 모두 ✓인데 「충족 0/1」(R02·R03·R13). ♥한 핀의 다른 라벨(예: 규모·붐빔 방향 값)이 숨은 선호로 집계되고 카드에는 충족한 것만 최대 5줄 보이기 때문. 설계(#620·#702)와 일치하지만 사용자에게는 모순으로 보임 → UI 문구/집계 기준 재검토.
- **F-5 시즌 밖 계절 키 무음 제외**: 7월에 "단풍"을 써도 줄은 활성으로 보이고 결과에서만 조용히 빠짐. 「이번 여행 기간에는 해당 없음」 안내 부재.
- **F-6 뉘앙스 손실**: "국물 있는 한식" → `cuisine_korean`만 반영, 국물 여부는 표현 불가(고기집 기왕생고기가 3위). 데이터/라벨 한계.
- **F-7 확인 필요 잡음**: 영업 시간 미수집(서울 음식점 시간 수집 중)이라 상당수 카드에 「영업 여부 확인 필요」. 종류를 전부 제외하면 카드에 「확인 필요」 6개가 붙는다.
