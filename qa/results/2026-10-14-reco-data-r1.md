# AI 추천 품질 시험 1차 — 2026-10-14 (데이터 담당)

환경: 앱 = 당시 develop(로컬 :8000) · DB = 로컬 개발 DB, 장소 104,391곳(정예 + 인허가 커버리지) · 모델 = `gpt-6-luna`(실제 호출) · 실행 = 데이터 담당 로컬 스크립트(`run_scenario.py`, 저장소 밖).
목적: 실제 사용자 흐름(핀 → 반응·사유 → 추천 → 결과)을 HTTP로 돌려 실제 데이터에서 추천 품질을 본다.

## 방법
- 동네 5곳(성수, 종로·익선, 홍대·연남, 강남, 잠실) × 카테고리별 사유 변형 = 시나리오 55개 + 같은 사유 5회 반복 25회 = 80회.
- 시나리오마다 새 사용자·지도, 정예 장소에 핀 + ♥/🚫 + 사유. 이름이 같은 장소가 30m 안에 또 있으면 핀이 거절돼(`PLACE_NOT_SUPPORTED`) 핀 후보에서 뺐다.
- 한계: "한식♥" 시나리오의 ♥ 핀이 실제로는 한식이 아니었고(동네 목록 맨 위 가게), 이유 칩은 시험하지 않았다 → 2차에서 다시.

## 발견

공통
- **D1-1 ♥ 핀 부수 특징이 직접 사유를 이김**: 직접 쓴 사유 1건 3점, ♥ 핀에서 온 키는 키마다 1점. ♥ 핀 라벨 3개면 동점, 4개면 역전. 이유 문구도 ♥ 핀 특징으로 채워짐(관광지 "야경이 예뻐요"의 이유가 "근현대 건축물, 사진, 쇼핑").
- **D1-2 인허가 커버리지가 추천 후보로 올라옴**: 커버리지는 핀·검색용인데 상위 3곳 중 음식점 80%, 카페 27%. 점수에 정예 여부가 없고 후보 수가 정예 약 1,570 대 커버리지 약 77,000.
- **D1-3 모름 통과, 거짓 감점 없음**: 요청한 조건이 모름·거짓인 장소도 상위에 남음.
- **D1-4 충족 집계 모순**: "선호 충족 … (0/1명)". 반대로 필수 조건이 모름인 곳이 "1/1명 충족"(잠실 스타벅스 잠실시그마타워점, `is_crowded_large`=모름).

음식점
- 술집이 음식점 추천에 나옴(홍대 새벽, 강남 느린마을 양조장&펍). 술집 판별 키가 없고 `serves_alcohol`은 정예 음식점 95%가 참이라 구별 불가.
- 이경문순대곱창: 업태 한식인데 이름 규칙("곱창")이 `cuisine_korean`을 거짓으로 덮음.
- 성수 "쉐이크쉑 성수"가 체인 🚫인데 3위(`franchise` 참만 있고 이 곳은 모름).
- 고기구이(`cuisine_bbq`)는 한식이 아님(#417) — "한식 좋아요"와 충돌하는 제품 결정 사항.

카페
- 정예 카페 `serves_alcohol` 1,496곳이 "직접 조사" 근거, 휴게음식점·제과점(법상 판매 불가)인데 참인 곳 7곳.

관광지
- 실내·실외가 둘 다 참인 곳 151곳(쌈지길 등) — `constraints.md` "섞이면 둘 다 모름" 위반. 성수연방 실내 여부 의문.
- 야경·산책 요청에 실내 시설(성수연방, 리얼월드 성수, 에스팩토리), 산책 ♥에 `walkable`=거짓인 코코넛박스.
- 사유와 가까운 키의 채움이 낮음: `night_view` 47%, `walkable` 35%, `photogenic` 23%, `date_spot` 15%.
- 강남은 반경 안 정예 관광지 2곳뿐이라 0건.
