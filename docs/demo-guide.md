# 팀 시연 따라 하기

핀고(pin-go-pin-go)를 내 컴퓨터에서 켜서 팀원 앞에서 보여 줄 사람을 위한 문서입니다. 개발을 몰라도 위에서부터 순서대로 복사해 붙여 넣으면 됩니다.

내 컴퓨터에 처음 설치한다면 `docs/team-setup-guide.md`(설치, 키 넣기, 켜기)를 먼저 보세요. 이 문서는 켠 뒤의 시연 순서입니다.
개발자용 자세한 점검표는 `docs/openapi-workflow.md` 5절에 따로 있습니다.

처음 한 번은 준비에 30분쯤 걸립니다(데이터 넣는 5분 포함). 그다음부터는 켜는 데 3분, 시연 10분이면 됩니다.

**심사에 내는 서비스 주소는 운영**(`https://ktc-pingopingo.duckdns.org`)입니다. 운영은 2026-11-08 `v0.1.0`이고 장소 데이터도 스테이징과 같은 2026-11-04판입니다(#1528). **발표에서 시연 지도를 띄워 보여 줄 때는 스테이징**(`https://staging.ktc-pingopingo.duckdns.org`)에서 합니다. 사람 셋이 없어도 시연 지도 스크립트가 상황을 만들어 두는데, 이 스크립트는 QA 로그인을 써서 스테이징에서만 돕니다(장면 8의 「스테이징에서 시연할 때」, #1301). 시연 영상도 스테이징에서 찍었습니다.
이 문서의 2~4절은 같은 시연을 내 컴퓨터(`localhost`)에서 따라 하는 방법입니다 — 연습할 때와, 서버가 끝난 뒤(2026-11-20, `deploy_rules.md` 「AWS가 끝나기 전에」)에 씁니다. 로컬에서는 같은 컴퓨터에서 브라우저 창 3개로 세 사람 역할을 합니다.

---

## 1. 준비물 체크리스트

시작 전에 아래가 다 있는지 확인하세요.

- [ ] 프로그램 4개: Docker Desktop, Python 3.12(실제 서버와 같은 버전입니다. 3.13 이상은 서버 부품 설치가 실패합니다), Node.js 20 이상, Git
- [ ] 저장소를 받아 둔 폴더(`git clone` 한 폴더)
- [ ] 데이터 폴더 `정예DB_final_2026-11-04_서울`(서울, 필수)와 `정예DB_final_2026-11-04_타지역`(다른 지역, 선택). 저장소 밖에 둡니다. 넣는 법은 `docs/team-setup-guide.md` 5-4에 있습니다.
- [ ] 키 3개
  - 카카오 REST API 키 (로그인과 장소 검색용)
  - 카카오 JavaScript 키 (지도 그리기용)
  - OpenAI API 키 (AI가 사유를 읽을 때 씁니다. 2026-11-02부터 엘리스 ML API가 아니라 OpenAI에서 발급합니다, #1120)
- [ ] 카카오 계정 2~3개 (사람 역할을 할 계정입니다. 한 명이 여러 창에서 서로 다른 계정으로 로그인합니다)
- [ ] 브라우저 두 개, 또는 일반 창과 시크릿 창 (계정을 나눠 로그인하려면 필요합니다)

키는 **절대 채팅이나 깃에 올리지 마세요.** 아래에서 만드는 `.env` 파일에만 넣습니다. 이 파일은 깃이 알아서 무시합니다.

## 2. 한 번만 하는 준비

### 2-1. 카카오 개발자 콘솔 설정 (https://developers.kakao.com)

내 애플리케이션을 열고 아래 세 가지를 합니다.

1. 카카오 로그인을 켭니다(활성화 ON).
2. Redirect URI에 아래 주소를 글자 하나 틀리지 않게 등록합니다.
   ```
   http://localhost:8000/auth/kakao/callback
   ```
3. 플랫폼의 Web 항목에 아래 주소를 등록합니다. 지도가 뜨려면 필요합니다.
   ```
   http://localhost:5173
   ```

그리고 앱 키 화면에서 두 가지를 메모해 둡니다.

- REST API 키는 아래 `KAKAO_CLIENT_ID`에 넣습니다.
- JavaScript 키는 아래 `VITE_KAKAO_MAP_KEY`에 넣습니다.

카카오 앱 설정에서 Client Secret을 켜 두었다면 그 값도 `KAKAO_CLIENT_SECRET`에 넣어야 합니다. 꺼 두었으면 비워 둡니다.

### 2-2. 백엔드(서버) 설정

터미널을 열고 저장소 안의 `backend` 폴더로 이동합니다.

```bash
cd backend
```

① 파이썬 부품 설치 (처음 한 번)
```bash
pip install -r requirements.txt
```

② 설정 파일 만들기. `backend/.env.example`을 복사해서 이름을 `backend/.env`로 바꿉니다. 그다음 `.env`를 메모장으로 열어 아래 값만 고치고 나머지는 그대로 둡니다.

| 줄 | 이렇게 적기 | 설명 |
|---|---|---|
| `PINGO_ENV=` | `dev` | 꼭 적기. 안 적으면 서버가 안 켜진다 |
| `PLACES_MODE=` | `real` | 진짜 장소 검색을 쓴다 (`dev`면 가짜 5곳만 나온다) |
| `LLM_MODE=` | `real` | 진짜 AI를 쓴다 (`dev`면 AI가 사유를 읽지 못한다) |
| `KAKAO_CLIENT_ID=` | 카카오 REST API 키 | `=` 바로 뒤에 붙여서 적는다. 공백이나 따옴표를 넣지 않는다 |
| `KAKAO_CLIENT_SECRET=` | (Client Secret을 켰을 때만) | 안 켰으면 줄을 비운다 |
| `KAKAO_REDIRECT_URI=` | `http://localhost:8000/auth/kakao/callback` | 2-1에서 등록한 것과 똑같이 |
| `ELICE_ML_API_BASE_URL=` | `https://api.openai.com/v1` | 변수 이름에 ELICE가 남아 있지만 OpenAI 주소를 넣는다 |
| `ELICE_ML_API_KEY=` | OpenAI 프로젝트 키 | 새로 받은 키 (틀리거나 지운 키는 `401`이 난다. 옛 엘리스 키는 쓸 수 없다) |

`.env`에 `AUTH_MODE=`로 시작하는 줄이 있으면 지워도 됩니다. 이제 쓰지 않는 설정입니다.

③ 데이터베이스 켜기 (Docker Desktop이 켜져 있어야 합니다)
```bash
docker compose up -d
```
줄이 몇 개 나오고 `Started`로 끝나면 성공입니다. 처음에는 이미지를 받느라 1~2분 걸립니다.

④ 데이터베이스에 표(테이블) 만들기
```bash
python -m alembic upgrade head
```
빨간 `Error`나 `Traceback` 없이 끝나면 성공입니다.

⑤ 가게 데이터 넣기 (약 5분, 딱 한 번만)

`docs/team-setup-guide.md` 5-4의 명령을 그대로 따릅니다. 넣는 순서나 `--authoritative`가 틀리면 AI 추천 후보가 줄어들기 때문에 명령은 그 문서 한 곳에만 적어 두었습니다.

### 2-3. 프론트(화면) 설정

새 터미널을 열고 저장소의 `frontend` 폴더로 갑니다.

```bash
cd frontend
npm install
```

`frontend` 폴더 안에 `.env.local` 파일을 새로 만들고 아래 두 줄을 넣습니다. 키는 본인 것으로 넣으세요.
```
VITE_API_BASE_URL=http://localhost:8000
VITE_KAKAO_MAP_KEY=여기에_카카오_JavaScript_키
```
`VITE_API_BASE_URL`을 적으면 연습용 가짜 서버가 꺼지고 진짜 서버에 붙습니다. 이 줄이 없으면 화면은 뜨지만 진짜 데이터가 아닙니다.

## 3. 시연할 때마다 켜는 순서

터미널 2개를 씁니다.

터미널 ① 서버
```bash
cd backend
docker compose up -d
python -m uvicorn main:asgi_app --port 8000
```
`Application startup complete.`가 나오면 켜진 것입니다. 이 창은 시연이 끝날 때까지 닫지 마세요.
브라우저에서 `http://localhost:8000/health`를 열어 `{"status":"ok"}`가 보이는지도 확인해 보세요.

터미널 ② 화면
```bash
cd frontend
npm run dev
```
`Local: http://localhost:5173/`가 나오면 브라우저에서 이 주소를 엽니다.

주소는 꼭 `localhost`로 여세요. `127.0.0.1`로 열면 쿠키가 붙지 않아서 로그인이 풀려 버립니다.

## 4. 시연 대본

먼저 세 사람의 역할을 정합니다. 사람이 적으면 2명이어도 되고, 한 사람이 창을 나눠 써도 됩니다.

| 역할 | 이름(예시) | 브라우저 |
|---|---|---|
| A 방장 | 지우 | 일반 창 |
| B 구성원 | 서연 | 시크릿 창 |
| C 구성원 | 민재 | 다른 브라우저(또는 두 번째 시크릿 창) |

시크릿 창끼리는 쿠키를 나누지 않아서 계정이 섞이지 않습니다.

### 장면 1. 로그인하고 지도 만들기 (A)

1. `http://localhost:5173`을 열고 '카카오로 시작하기'를 누릅니다.
2. 카카오 로그인 화면에서 A 계정으로 로그인하고 동의합니다.
3. '새 지도 만들기'에서 제목 `성수 팀 시연`과 기간(예: 11월 1일~2일)을 넣고 '지도 만들기'를 누릅니다.
   - 지도 화면이 열리고 아래에 마킹된 장소, AI 추천, 확정된 장소 탭 3개가 보입니다.

### 장면 2. 친구 초대하기 (A가 B, C를)

1. 화면 위쪽의 지도 정보(구성원 아이콘)를 열고 '초대 링크 공유하기'를 눌러 링크를 복사합니다.
2. B 창과 C 창에서 그 링크를 열고, 각자 계정으로 로그인한 뒤 '참여하기'를 누릅니다.
   - A 화면의 구성원 목록에 3명이 보이고, A에게 방장 표시가 붙어 있습니다.

### 장면 3. 핀 찍기 (모두)

검색창에 가게 이름을 그대로 쓰고 엔터를 누른 뒤, 나온 결과에서 '핀 찍기'를 누릅니다.

| 누가 | 검색창에 쓸 말 | 결과 |
|---|---|---|
| A | `기왕생고기` | 기왕생고기 |
| B | `텐바` | 텐바 |
| C | `용용선생 마라도원` | 용용선생 마라도원 |
| A | `성수노루` | 성수노루 |
| B | `라이홍` | 라이홍 |

**`성수 삼겹살`처럼 음식 이름으로 검색하면 안 됩니다.** 새 지도는 서울 중심에서 시작하고 검색 결과는 지도 중심에서 가까운 순이라서, 성수가 아닌 가게가 먼저 나오고 대본의 가게는 10곳 안에 들지 않습니다(점검에서 확인했습니다). 위 표처럼 가게 이름 그대로 검색하면 결과가 1곳만 나오고 지도가 성수로 옮겨 갑니다.

- 한 사람이 핀을 찍으면 몇 초 안에 다른 창에도 핀이 나타납니다. 새로고침하지 않아도 됩니다.
- 지도 아래 마킹된 장소 탭에 5곳이 목록으로 보입니다.

검색 결과에는 "장소 정보가 없는 핀이에요"라고 흐리게 나오는 가게가 많습니다(음식 이름으로 검색했을 때 열에 아홉 정도). 우리 데이터에 없는 가게라서 장소 정보, AI 추천, 동선은 없습니다. 그래도 '그래도 핀 남기기'를 누르고 메모(예: "여기 곱창 맛있대")를 적으면 핀으로 남길 수 있고 ♥/🚫 의견도 달 수 있습니다(#382). 위 표의 가게는 장소 정보까지 다 나옵니다.

이런 핀은 지도를 열 때마다 카카오에서 위치를 다시 찾아 그립니다. 가게가 없어졌거나 이름이 바뀌었으면 "위치를 불러오지 못했어요"로 목록에만 보입니다.
같은 가게를 두 번 찍으면 "이미 지도에 있는 장소예요"가 나오는데, 이것도 정상입니다.

### 장면 4. 의견 남기기 (모두)

핀을 눌러 열고 반응을 고릅니다. ♥는 좋아요, 🚫는 반대입니다.

| 누가 | 어느 핀 | 반응 | 내용 |
|---|---|---|---|
| A | 기왕생고기 | ♥ | (그냥 누르면 됨) |
| B | 텐바 | ♥ | (그냥 누르면 됨) |
| C | 용용선생 마라도원 | 🚫 | 사유 칩에서 "매워요" 선택 |
| A | 성수노루 | ♥ | 사유에 `조금 느끼한 것 같아요` 라고 써도 됩니다(사유는 선택) |

- 🚫 반대는 사유 없이는 등록되지 않습니다. 칩이나 글 중 하나는 꼭 있어야 하는 게 핀고의 규칙입니다.
- 다른 창에 "○○님이 반대 의견을 남겼어요" 알림이 뜹니다.
- 마킹된 장소 위쪽에 "3/3명이 의견을 남겼어요" 같은 문구가 보입니다.

### 장면 5. AI 추천 받기 (A만)

1. 아래 AI 추천 탭을 누르고 카테고리는 음식점으로 둡니다.
   - 그 카테고리에 ♥나 🚫 의견이 달린 핀이 하나도 없으면 "의견이 모여야 추천이 열려요"가 나옵니다. 핀 하나에라도 의견이 있으면 열리고, 혼자 쓰는 지도도 똑같습니다(2026-10-07 변경).
2. 추천을 시작하고, AI가 사람들의 사유를 읽는 동안 5~10초 기다립니다. 예전처럼 확인 화면이 먼저 뜨지 않고 바로 결과가 나옵니다(2026-10-30 변경).
3. 결과 위에 "이 조건으로 찾았어요"가 나옵니다. 여기가 시연의 핵심입니다.
   - "매운맛 전문 제외" (민재의 "매워요")
   - "기름진 메뉴 위주 제외" (지우의 "조금 느끼한 것 같아요")
   - "#가격대 제외" (민재의 "가격이 조금 부담돼요". 가격은 지금 걸러 내지 않고 표시만 합니다)
   - 이렇게 AI가 사람 말을 조건으로 바꿔 보여 줍니다. 잘못 읽었으면 줄 옆의 − 버튼으로 빼고 '다시 추천 받기'를 누르면 고친 조건으로 다시 찾습니다. 이미 보인 후보는 빼고 새로 찾습니다. 직접 조건을 쓰고 싶으면 + 로 추가합니다.
   - 드물게(점검 8번 중 1번) AI가 조건으로 정리하지 못하고 "매워요"처럼 말을 그대로 보여 줄 때가 있습니다. 말 그대로 보이는 줄은 후보를 거르지 못하니, "제외"가 붙어 있지 않은 줄은 −로 빼고 '다시 추천 받기'를 눌러 보세요.
4. 지역 확인 단계는 지금은 없습니다. 검색할 동네 원은 자동으로 정해집니다.
5. 결과로 추천 가게가 3곳 나옵니다. 예를 들면 `맛보래`, `부산밀면`, `주식회사 식당컴퍼니 소바식당`인데, 컴퓨터 상태에 따라 가게는 달라질 수 있습니다.
   - 가게마다 추천 이유, 조건 체크 칩("기름진 메뉴 위주 아님", "매운맛 전문점 아님", "한식" 등. "영업 여부 확인 필요"는 아직 확인하지 못했다는 뜻입니다), "2명 중 2명 충족" 같은 충족 표시, 출처가 붙어 있습니다.
   - B, C 화면에는 아직 추천 가게가 보이지 않습니다. AI 추천은 요청한 사람(A)에게만 보이고, A가 '지도에 올리기'를 눌러야 모두에게 공개됩니다. 핀고의 첫 번째 약속입니다.
6. 마음에 드는 가게 하나에서 '지도에 올리기'를 누릅니다.
   - B, C 화면에도 그 핀이 점선 모양(AI 추천)으로 나타나고, 추천 이유도 그대로 남아 있습니다.

결과가 마음에 안 들면 반경 넓히기(동네를 더 넓게)나 다시 추천을 눌러 여러 번 해 볼 수 있습니다.

'추천받기'는 누를 때마다 크레딧 1을 씁니다(#432). 카카오로 로그인한 계정은 30으로 시작하고, 버튼 아래에 "1 크레딧 사용 · 남은 크레딧 29/30"처럼 보입니다. '다시 추천'과 근거 고치기는 크레딧을 쓰지 않고, 게스트는 AI 추천을 쓸 수 없습니다.
크레딧이 바닥나면 "크레딧이 부족해요"가 뜹니다. 장소 후기를 그 장소에 처음 쓰면 10을 받습니다.

### 장면 6. 확정 리스트와 일정 (A)

1. 가고 싶은 핀을 열어 '★ 확정 리스트에 넣기'를 누릅니다. 3곳 정도면 됩니다.
2. 확정된 장소 탭에서 장소 앞의 체크박스를 고르고, 아래에 붙는 막대에서 날짜를 고른 뒤 'N곳 넣기'를 누릅니다. PC 화면이면 '일정 짜기' 패널을 열고 ≡를 끌어 날짜 칸에 넣어도 됩니다.
   - 넣은 곳은 리스트에서 빠지고 그 날짜의 일정에 들어갑니다.
3. '동선 보기'를 켜고 날짜를 고릅니다.
   - 그날 장소가 넣은 순서대로 나오고, 2곳부터는 지도에 순서대로 선과 번호가 그어집니다. '카카오맵에서 길찾기'를 누르면 그 순서로 길찾기가 열립니다.
   - 날짜와 순서는 사람이 정합니다. 핀고는 일정을 자동으로 만들지 않아서 "몇 시에 어디"는 나오지 않습니다.

### 장면 7. AI 코스 짜기 (A)

확정한 곳을 AI가 날짜별 순서로 나눠 줍니다(#334). 장면 6에서 확정한 곳이 2곳 이상이면 되고, 4~5곳으로 늘리면 날짜 나누기가 잘 보입니다.

1. 확정된 장소 탭 머리의 'AI 코스 짜기'를 누릅니다.
2. '요청 한 줄' 칸에 아래처럼 씁니다. 비워 둬도 코스는 나옵니다.
   - `첫날엔 성수노루 꼭 가고 싶고, 많이 걷기 싫어요`
3. '코스 짜기'를 누르고 10~20초 기다립니다.
   - 처음 몇 초는 핑고가 "요청을 읽고 있어요"라고 나옵니다.
   - 이어서 작업 기록이 한 줄씩 쌓입니다. 첫 줄은 파란 카드로 "이렇게 이해했어요: 성수노루를 첫째 날에 · 하루 걷는 시간 줄이기"가 나오고, 아래 줄마다 역할(해석, 지휘, 계산, 검증, 결정)과 누가 했는지(AI, 코드, 사람)가 붙어 있습니다.
   - 여기서 보여 줄 것은 AI가 사람 말을 목표로 바꾸고 계산을 지휘할 뿐, 코스 계산과 확인은 코드가 한다는 점입니다.
4. 결과
   - 요청한 것: 목표마다 "지킴" 또는 "못 지킴"이 붙습니다.
   - 날짜별 카드: 순서, 구간마다 "도보 N분"(동네가 다르면 "대중교통 약 N분"), '카카오맵에서 길찾기' 링크가 있습니다.
   - 모든 장소에 "? 영업 확인 필요"가 붙습니다. 아직 영업일 정보를 넣지 않아서 그런 것이니 정상입니다.
   - B, C 화면에는 보이지 않습니다. 결과는 요청한 사람에게만 보이고 지도와 확정 리스트도 바뀌지 않습니다.
5. (선택) 확정 리스트에 없는 종류를 요청해 봅니다: `첫날엔 시장 구경하고 싶어요`
   - "확정 리스트에 시장·쇼핑 장소가 없어요"가 나옵니다. AI가 없는 장소를 지어내지 않고 없다고 말합니다.

AI 코스 짜기도 한 번에 크레딧 1을 씁니다(AI 추천과 같은 크레딧). 결과는 요청한 사람에게만 보이고 장면 6에서 짠 일정을 바꾸지 않습니다.
`.env`가 `LLM_MODE=dev`이면 AI 없이 코드만으로 코스를 짭니다. 코스는 나오지만 요청 한 줄은 "반영하지 못했어요"로 남습니다. AI까지 보려면 `LLM_MODE=real`로 두세요.

### 장면 8. 핑고 AI 조언 (모두)

핑고는 아무도 부르지 않아도 지도를 살펴보고, 막힌 곳을 찾아 먼저 제안합니다(`docs/agent-v2.md` 1.1). 평소에는 서버가 5분마다 살펴보지만 시연에서는 손으로 한 번 돌립니다.

1. 막힌 상황 만들기. 장면 5에서 음식점 추천을 이미 받았으니, B가 음식점 핀 하나에 🚫를 새로 남깁니다(예: 칩 "웨이팅이 길어요"와 "한 시간 넘게 기다렸어요"). 그 뒤에 B와 C가 카페 핀에 ♥를 하나씩 누릅니다.
   - 반대가 나온 뒤로 다른 카테고리에서만 사람이 움직였으니, 음식점이 반대 뒤로 멈춘(정체) 상황이 됩니다. 두 사람이 움직이면 몇 시간을 기다리지 않아도 됩니다.
   - 그사이 음식점 핀을 새로 찍거나 음식점 AI 추천을 받으면 막힌 게 아니라서 제안이 나오지 않습니다.
2. 핑고에게 살펴보게 하기. 서버를 켠 `backend` 폴더에서, 가상환경을 켠 터미널로 아래를 실행합니다.
   ```
   python -m agent.tick
   ```
   - 지도가 많으면 한 번에 6곳씩 봅니다. 제안이 안 보이면 2~3번 더 돌립니다.
3. A 화면 지도 왼쪽 아래 '핑고 AI 조언'을 누릅니다. 새 제안이 있으면 버튼에 점이 찍혀 있습니다.
   - 맨 위에 "AI" 지도 현황이 나옵니다: "…출발이 7일 남았으니 음식점부터 보면 좋겠어요".
   - 제안 카드에는 "음식점 후보가 반대 의견 뒤로 멈춰 있어요", 반대 사유를 인용한 문장, "지금 조건으로 추천에 남는 곳이 N곳 있어요"가 나옵니다. N곳은 추천을 받기 전에 핑고가 미리 세어 본 수이고, 0곳이면 추천 버튼을 아예 내지 않습니다. 반대 사유에 걸리는 곳도 빼지 않고 순위만 낮추므로(#1253) "반대 사유를 지키는 곳"이라고 말하지 않습니다.
   - 우리 데이터 줄에는 "우리 데이터로는 ○○이 매운맛 전문인지 몰라요"처럼 나옵니다. 모를 때는 핑고가 웹에서 찾아본 문장과 출처 링크를 "확인되지 않음" 표시와 함께 붙이고, 못 찾으면 "웹에서도 찾지 못했어요"라고 씁니다.
   - '핑고가 한 일 보기'를 펼치면 감지, 조사(AI가 고른 도구), 미리 찾기, 우리 데이터, 웹 확인, 검증, 재확인 순으로 나오고, 줄마다 AI가 했는지 코드가 했는지 붙어 있습니다(#1297. 서버나 화면에 아직 반영되지 않았으면 이 토글이 없습니다).
   - B, C 화면에도 같은 제안이 보입니다. 지도 제안은 모두에게 공개됩니다. 한 사람이 열어 봐도 다른 사람 화면의 점은 그대로입니다.
4. '음식점 추천 받기'를 누르면 AI 추천 탭으로 넘어가 장면 5처럼 추천이 시작됩니다. 핑고는 버튼만 내주고 실행은 사람이 합니다.
5. (선택) 의견 갈림 보여 주기. 카페 핀 하나에 B가 ♥ "조용해서 이야기하기 좋아요", C가 🚫 "주차가 안 돼서 차로 가기 불편해요"를 남기고, 마지막으로 A가 ♥를 누른 뒤 `python -m agent.tick`을 돌립니다.
   - "의견이 갈린 핀이 있어요", "어디서 갈리나요"(♥ 쪽은 조용한 곳, 🚫 쪽은 주차), "♥ 쪽 조건(조용한 곳 원함), 🚫 쪽 조건(주차 가능 원함)에 어긋나지 않는 곳이 N곳 있어요. 그중 M곳은 둘 다 우리 데이터로 확인됐어요"가 나옵니다. 두 의견에 어긋난다고 확인된 곳만 빼고 세고, 그중 둘 다 확인된 곳을 따로 셉니다(#1600). 확인된 곳이 없으면 뒷문장 대신 "가게에 확인이 필요해요"가 나옵니다.
   - 지도 하나에 제안은 하나씩만 나오니, 1번 제안을 닫거나 수락한 뒤에 해 보세요.

**스테이징에서 시연할 때**는 사람 셋이 없어도 됩니다. 서버에서 시연 지도 스크립트가 QA 구성원 둘을 만들어 위 상황을 만들어 두고, 발표자는 초대 링크로 들어와 보기만 하면 됩니다(#1301).
```
cd /srv/pingo/deploy
curl -fsSL https://raw.githubusercontent.com/kakaotechcampus-4/ktc4-chungnam-2/develop/qa/harness/seed_agent_demo.py   | ./run.sh staging python - --base-url https://staging.ktc-pingopingo.duckdns.org/api --tick
```
- 출력에 나오는 "발표자 초대 링크"를 발표자 계정(카카오 로그인)으로 엽니다. `--tick`은 제안이 뜰 때까지 관찰을 돌리고 "tick N번 만에 제안이 떴다"를 출력합니다.
- 갈림을 보여 주려면 `--scenario split`을 붙입니다. 스크립트가 발표자가 들어오기를 15분까지 기다렸다가 QA 둘의 ♥와 🚫를 남기고, 발표자가 그 카페 핀에 ♥를 누르면 다음 관찰에 제안이 뜹니다. 발표 중에 라이브로 보여 주기 좋습니다.
- '추천 받기'는 발표자의 크레딧 1을 씁니다(정식 계정은 30으로 시작).
- 사유 글을 바꾸려면 `--reason "…"`(1~140자)을 씁니다. 따옴표, 이모지, 긴 글이 깨지지 않는지 보는 QA G04에 씁니다. 60자보다 길게 인용한 문장은 검증 단계에서 빠집니다(작업 기록의 검증 줄에 "맞지 않은 1개는 뺐어요").
- **수락한 뒤에도 핑고가 지켜보는 장면**(#1345)은 `--followup stuck`을 붙입니다. 스크립트가 제안을 수락하고 30분을 실제로 기다린 뒤 카페에 핀을 찍어 「음식점은 그대로」를 만듭니다. 그러면 시트에 「지켜보는 중」 → 「두 번째 방법」(해 본 것: 음식점 추천 받기, 버튼: 음식점 검색) → 한 번 더 기다리면 「충돌 선언」(버튼 없이 해 본 것만 남김)이 차례로 나옵니다. 약 한 시간 걸리니 **발표 전에 미리 돌려 둔 지도**로 보여 줍니다. 수락은 버튼의 동작만 돌려받는 것이라 추천도 크레딧도 쓰지 않습니다.
- 「풀렸어요」를 보이려면 `--followup resolve`입니다. 수락 뒤 음식점에 새 핀을 찍어, 다음 관찰에 지켜보는 곳이 「풀렸어요」로 바뀝니다(기다림 없음).
- 이 장면은 이렇게 말합니다: "핑고는 제안하고 끝나지 않아요. 풀렸는지 계속 보고, 그대로면 해 본 것과 다른 방법을, 그래도 안 되면 무엇을 해 봤는지 남기고 결정은 여러분께 돌려드려요."

이 장면은 이렇게 설명하면 좋습니다.

> - "아무도 핑고를 부르지 않았어요. 핑고가 5분마다 지도를 보다가 반대 뒤로 멈춘 곳을 스스로 찾았어요."
> - "핑고는 사유를 읽고(도구), 추천 받으면 몇 곳이 남는지 미리 세 보고, 가게 정보를 우리 데이터와 웹에서 확인한 뒤에 제안해요."
> - "AI가 쓴 숫자와 인용은 코드가 지도와 대조해요. 틀린 건 빼고, 결정을 강요하는 말('확정하세요')은 화면에 나가지 않아요."
> - "핑고는 아무것도 직접 하지 않아요. 버튼은 사람이 원래 하던 동작의 지름길이에요."

여기까지 하면 시연이 끝납니다. 이 흐름으로 핀고의 핵심 약속을 모두 보여 줄 수 있습니다.

시연 중에는 이렇게 설명하면 좋습니다.

> - "AI는 지도를 마음대로 바꾸지 않아요. 제안은 나한테만 보이고, 내가 올려야 모두에게 보여요."
> - "안 맞는 가게는 AI가 아니라 코드가 걸러요. AI는 사람 말을 조건으로 바꾸는 일만 해요."
> - "아니라고 확인된 가게만 남기고, 모르는 가게는 안전을 위해 빼요."
> - "코스 짜기에서는 AI가 매번 다음 수를 스스로 골라요(다시 짜 보기, 장소 고정, 끝내기). 계산은 코드가 하고, AI 말이 계산과 다르면 코드가 문장을 바꿔요."
> - "AI가 응답을 못 해도 그 턴은 코드가 이어받고 작업 기록에 그렇게 적어요. 코스는 끝까지 나와요."
> - "안 맞는 가게를 거르는 일은 한 명이라도 걸리면 안 돼서 AI에 맡기지 않았어요. AI는 답이 하나가 아닌 곳(사람 말 읽기, 절충안 고르기)에만 써요."

## 5. 문제가 생기면

| 이런 일이 생겼다 | 왜 그럴까 | 이렇게 해 보세요 |
|---|---|---|
| '핑고 AI 조언'에 제안이 안 나온다 | 정체 조건이 안 맞거나(반대 뒤로 그 카테고리 핀을 새로 찍음, 추천을 받음, 확정함), 지도가 많아 아직 차례가 안 됨 | `python -m agent.tick`을 2~3번 더. 시트에 "이번에는 지도를 끝까지 살펴보지 못했어요"가 보이면 AI 호출이 실패한 것이니 `.env`의 `LLM_MODE=real`과 키 확인 |
| 웹 요약 대신 "오늘은 웹 확인을 쉬고 있어요" | 하루 웹 확인 예산(3,000원)을 넘었다 | 정상 동작. 다음 날 풀린다(`LLM_DAILY_BUDGET_KRW`) |
| 서버가 안 켜지고 `ConfigError` 가 뜬다 | `.env` 에 `PINGO_ENV=dev` 가 없다 | `backend/.env` 에 `PINGO_ENV=dev` 를 적고 다시 켠다 |
| `relation "..." does not exist` | 표를 아직 안 만들었다 | `python -m alembic upgrade head` |
| 로그인 버튼을 누르면 카카오에서 KOE006 오류 | Redirect URI가 콘솔과 `.env` 에서 다르다 | 둘이 `http://localhost:8000/auth/kakao/callback` 으로 글자까지 똑같은지 확인 |
| 카카오 로그인 후 계속 로그인 화면으로 돌아온다 | 주소를 `127.0.0.1` 로 열었다 | 주소를 `http://localhost:5173` 으로 연다 |
| 로그인 도중 "로그인을 취소했어요" 같은 안내가 뜬다 | 카카오 화면에서 취소를 눌렀다 | 다시 로그인 버튼을 누른다 |
| 지도가 안 보이고 회색이다 | 지도 키가 없거나 도메인 미등록 | `frontend/.env.local` 의 `VITE_KAKAO_MAP_KEY` 와 카카오 콘솔의 Web 도메인(`http://localhost:5173`) 확인 후 `npm run dev` 를 껐다 켠다 |
| 검색하면 "장소 검색을 지금은 쓸 수 없어요" | 카카오 REST 키가 없거나 틀리다 | `.env` 의 `KAKAO_CLIENT_ID` (앞에 공백이 없는지), `PLACES_MODE=real` 확인 후 서버를 껐다 켠다 |
| 검색 결과가 전부 흐리다 | 그 가게들이 우리 데이터에 없다 | 위 표(장면 3)의 가게로 다시 검색해 본다 |
| 추천 받기가 실패했어요 | AI 키가 만료되었거나 틀렸다 | `ELICE_ML_API_KEY` 를 새 키로 바꾸고 서버를 껐다 켠다. 서버 창에 `401` 이 보이면 키 문제다 |
| 추천이 0곳이다 | 조건에 맞는 가게가 반경 안에 없다 | 반경 넓히기를 누르거나, 핀을 가게가 많은 동네(명동, 홍대 등)에 찍어 본다 |
| 추천이 계속 안 켜진다("의견이 모여야 추천이 열려요") | 그 카테고리(음식점)에 ♥/🚫 의견이 달린 핀이 하나도 없다 | 음식점 핀 하나에 ♥나 🚫를 남긴다 |
| 핀이 다른 창에 안 나타난다 | 실시간 연결이 끊겼다 | 화면의 '다시 연결' 버튼을 누르거나 새로고침(F5) |
| 'AI 코스 짜기' 버튼이 흐리다 | 위치를 아는 확정 장소가 2곳보다 적다 | 확정 리스트에 장소 정보가 있는 핀을 2곳 이상 넣는다('그래도 핀 남기기'로 만든 핀은 위치를 몰라 동선에서 빠집니다) |
| AI 코스에서 `relation "agent_course_runs" does not exist` | 새 표를 아직 안 만들었다 | `python -m alembic upgrade head` |
| 추천받기나 AI 코스 아래에 "크레딧이 부족해요" | 크레딧을 다 썼다(1번에 1, 처음 30) | 아직 안 쓴 카카오 계정으로 하거나, 장소 후기를 그 장소에 처음 써서 10을 받는다 |
| AI 코스가 "요청을 읽고 있어요"에서 오래 멈춘다 | 브라우저 창이 가려져 있으면 조회가 잠시 멈춘다 | 그 창을 앞으로 띄운다. 서버 창에 `동선 지휘 턴 성공` 이 보이면 서버는 정상이다 |
| AI 코스 요청 한 줄이 전부 "반영하지 못했어요" | `LLM_MODE=dev` 이거나 AI 키 문제 | `.env` 의 `LLM_MODE=real`, `ELICE_ML_API_KEY` 확인 후 서버를 껐다 켠다 |
| 아예 처음부터 다시 하고 싶다 | | 새 지도를 만들면 됩니다. 이전 지도는 그대로 둬도 아무 문제 없어요 |

서버 창(터미널 ①)에 나오는 빨간 글자에는 대부분 원인이 적혀 있습니다. 막히면 그 글자를 개발자에게 그대로 보여 주세요.

## 6. 시연 전에 알아 둘 것

- 가게는 서울 음식점과 카페만 있습니다. 관광지는 추천 후보가 없으니 시연에서는 음식점만 하세요.
- 핀은 한 동네(예: 성수)에 모아서 찍으세요. 성수와 홍대처럼 서로 멀리 떨어진 가게만 있으면 둘 사이 빈 땅을 기준으로 찾아서 추천이 비어 보입니다. 알려진 한계입니다(#226).
- AI 추천이 5~10초 걸리는 건 정상입니다. AI가 사람 말을 읽는 시간이고, 사유가 아주 많으면 20초까지 걸릴 수 있습니다.
- 알러지(갑각류 등)는 걸러 주지 않습니다(#425). 우리 데이터로 "갑각류 없음"을 보장할 수 없어서, 추천 결과에 "알러지가 있다면 가게에 직접 확인해 주세요"를 띄웁니다. 반면 매운맛이나 기름짐은 취향이라서, 🚫 "매워요"를 남기면 매운맛 가게로 확인된 곳만 빠지고 모르는 가게는 "확인 필요"를 달고 남습니다(2026-10-07).
- AI 코스 짜기는 순서와 이동 시간만 보여 줍니다. 이동 시간은 직선거리로 어림한 값이고(2km가 넘으면 대중교통으로 계산), 정확한 길은 카카오맵 링크로 확인합니다. "몇 시에 어디"는 만들지 않습니다.
- AI가 사람 말을 잘못 읽을 수 있어서, 결과 화면의 "이 조건으로 찾았어요"에서 사람이 확인하고 −로 뺀 뒤 다시 찾을 수 있게 만들었습니다. 2026-10-30부터는 이 확인 화면이 결과 앞이 아니라 결과 안에 있습니다.
- 이 시연은 내 컴퓨터에서만 열립니다. 다른 사람이 인터넷으로 접속할 수는 없습니다.

## 7. 끝낼 때

- 터미널 ①, ②에서 `Ctrl + C`를 눌러 서버와 화면을 끕니다.
- 데이터베이스는 `backend` 폴더에서 `docker compose stop`으로 끕니다. 데이터는 그대로 남고, 다음에 `docker compose up -d`로 다시 켜면 됩니다.
- **`docker compose down -v`는 쓰지 마세요.** 데이터가 전부 지워져서 2-2의 ⑤를 다시 해야 합니다.

## 8. 시연 영상 촬영 대본 (5분)

심사 제출용 시연 영상을 찍는 팀용 절입니다. 장면 순서, 사용자 동작, 서비스 동작은 루트의 `시연시나리오.md`(제출용)가 정본이고, 이 절은 촬영할 때만 필요한 것을 적습니다. 가편집 영상(애니매틱)은 https://claude.ai/artifact/SH9XuUihnHjMoKuV78LV49 이고, 공유를 열어야 팀이 볼 수 있습니다.

### 8.1 촬영 원칙

1. 지도 하나, 이야기 하나로 갑니다. 같은 일행이 멈춤에서 확정까지 가는 동안 필요한 기능만 나오게 합니다.
2. 자막을 두 겹으로 둡니다. 내레이션은 제품의 말로, 화면 아래 작은 자막은 기술 사실(도구, 단계, 검증)로 씁니다.
3. AI와 코드를 색으로 가립니다. 앱의 "핑고가 한 일"과 같은 파란 AI 칩, 회색 코드 칩을 자막에도 씁니다.
4. 사람이 끼는 곳은 결정 하나라고 내레이션이 분명히 말합니다.
5. 꾸미지 않습니다. 배포 주소, 실제 모델 응답, 실제 계정으로 찍고, 자르는 것은 기다림뿐입니다. 자른 자리에는 "실제 4분 뒤"처럼 적습니다. 모델 문장은 여러 번 찍어 고르되 고치지 않습니다.

### 8.2 등장인물과 세트

- 지우: 방장, 카카오 계정, 크레딧 4 이상(추천 받기와 AI 코스 재촬영 몫). 영상의 주 화면입니다
- 서연: 초대 링크로 들어온 게스트
- 민재: 카카오 계정
- 지도: "서울 2박 3일". 성수(카페, 음식점)와 종로(경복궁, 덕수궁 등)를 함께 넣고, 확정 장소를 8곳 넘게 날짜에 넣어 둡니다. 코스 장면을 다른 지도에서 찍으면 이야기가 끊깁니다
- 화면: 16:9 화면에 폰 비율 창 셋을 나란히 둡니다. 주 화면만 크게 하고 주소창이 보이게 합니다

### 8.3 장면별 촬영 메모

장면 번호는 `시연시나리오.md`의 번호입니다.

- 장면 3: 다른 카테고리에서 두 사람이 움직이는 순간 "반대 후 정체"가 성립합니다. 그 사이 카페 핀을 새로 찍거나 카페 추천을 받으면 제안이 나오지 않습니다.
- 장면 4: 멘토용으로 서버의 관찰 처리량 로그 한 줄을 2초 넣습니다(지도 id 없음). "핑고가 한 일"은 줄마다 2초씩 멈추고, 아래 자막은 그 실행의 실제 작업 기록에서 옮깁니다.
- 장면 5: "이 조건으로 찾았어요"의 "붐비는 대형 카페 제외" 줄을 장면 3의 칩 화면과 반반으로 붙입니다.
- 장면 7: 버튼은 누르지 않습니다.
- 장면 8: 시드 지도 이름과 QA 구성원 이름은 잘라 내고 "다른 지도에서 미리 돌려 둔 장면"이라고 자막을 답니다.
- 장면 9: 문장은 실행마다 조금씩 다르니 2~3번 찍어 고릅니다. 기다림은 자르고 "실제 N초"를 적되, 작업 기록이 쌓이는 앞 몇 줄은 자르지 않습니다.
- 장면 11: 끝 카드는 3초 넘게 둡니다. 멘토용 마지막 컷으로 GitHub Actions의 backend-test, e2e, deploy 통과 표시를 넣습니다.

### 8.4 촬영 전 준비

1. QA G07~G11을 스테이징 화면으로 먼저 돌립니다. 장면 6, 8, 9가 여기에 달려 있고 아직 실행 전입니다. 하나라도 실패하면 그 장면을 빼고 장면 4를 늘립니다.
2. 찍을 주소: 영상은 스테이징에서 찍었습니다. 운영은 그 뒤 2026-11-08 `v0.1.0`으로 같은 기능이 올라갔고, 장소 데이터도 같은 판입니다(#1528). 다시 찍게 되면 시연 지도 스크립트가 도는 스테이징에서 찍습니다.
3. 카페를 고릅니다. 서연이 반대할 카페는 120㎡ 이상인 큰 카페여야 깔때기에 "실격 조건 제거"가 보입니다. 우리 데이터 줄과 웹 요약이 같이 나오는 곳은 리허설에서 2~3곳을 돌려 보고 고릅니다.
4. 장면 7 음식점을 고릅니다. 주차 라벨이 참인 곳이 가장 깔끔하고, 모름이면 웹 요약이 나오는지 리허설에서 봅니다. "같은 키, 같은 방향" 갈림은 QA 케이스에 없으니 `--scenario split`의 사유만 바꿔 미리 돌려 봅니다.
5. 장면 9 일정을 맞춥니다. 2일차에 그날 정기 휴무인 곳(예: 화요일의 경복궁)이 들어가도록 여행 날짜와 확정 일정을 정하고, 일정 점검 제안이 뜨는지 확인합니다.
6. 장면 8 지도는 전날 만듭니다. 약 1시간 걸립니다.

   ```bash
   cd /srv/pingo/deploy
   curl -fsSL https://raw.githubusercontent.com/kakaotechcampus-4/ktc4-chungnam-2/develop/qa/harness/seed_agent_demo.py \
     | ./run.sh staging python - --base-url https://staging.ktc-pingopingo.duckdns.org/api --tick --followup stuck
   ```

7. 크레딧과 예산을 확인합니다. 지우 계정에 크레딧이 4 이상 있어야 합니다. 서비스 하루 예산(3,000원)을 넘기면 웹 확인이 쉬므로 오전에 찍습니다.
8. 순서를 지킵니다. 지도당 활성 제안은 하나뿐이라 장면 7은 장면 6의 "풀렸어요"를 본 뒤에 찍습니다. AI 코스는 지도와 일정을 바꾸지 않으므로 장면 9는 마지막에 찍어도 됩니다.
9. 폰 알림을 끄고, 단톡방 이름과 프로필에 실명이 보이지 않게 합니다.

### 8.5 안 될 때

- 제안이 안 뜨면 다음 관찰(5분)을 기다리거나 사유를 다시 남깁니다. 관찰 한 번은 지도 6곳만 보므로 차례가 늦을 수 있습니다.
- 진단이 실패하면 "이번에는 지도를 끝까지 살펴보지 못했어요" 안내가 뜹니다. 이 화면을 장면 10의 실패 대응 컷으로 써도 됩니다. 꾸며서 채우지 않습니다.
- 웹 요약이 "웹에서도 찾지 못했어요"로 나오면 그대로 씁니다. 내레이션은 "모르면 모른다고 말해요"로 바꿉니다.
- AI 코스가 오래 걸리면 기다림을 자르고 "실제 N초" 자막을 넣습니다. 실패하면 "다시 짜기"로 한 번 더 찍습니다(실패한 실행의 크레딧은 돌려받습니다).
