# 팀 시연 가이드 — 따라 하기

> **이 문서는 누구를 위한 것인가?** 핀고(pin-go-pin-go)를 내 컴퓨터에서 켜서 팀원 앞에서 보여 주려는 사람.
> 개발을 몰라도 **위에서부터 순서대로 복사해서 붙여 넣으면** 됩니다.
> **내 컴퓨터에 처음 설치하는 거라면 `docs/team-setup-guide.md`를 먼저 보세요**(설치·키 넣기·켜기). 이 문서는 켠 뒤의 시연 순서입니다.
> 개발자용 자세한 점검표는 `docs/openapi-workflow.md` 5절에 따로 있습니다.

**걸리는 시간**: 처음 한 번 준비 약 30분(데이터 넣는 5분 포함) → 그다음부터는 켜는 데 3분, 시연 10분.
**배포는 하지 않습니다.** 모든 것이 내 컴퓨터(`localhost`) 안에서만 돌아갑니다. 같은 컴퓨터에서 브라우저 창 3개로 세 사람 역할을 합니다.

---

## 1. 준비물 체크리스트

시작 전에 아래가 다 있는지 확인하세요.

- [ ] **프로그램 4개**가 설치되어 있다: Docker Desktop, Python 3.10 이상, Node.js 20 이상, Git
- [ ] **저장소**를 받아 두었다 (`git clone` 한 폴더)
- [ ] **데이터 폴더** `식당카페_라벨_2026-10-02` (안에 `restaurant_seoul_curated.csv`, `cafe_seoul_curated.csv` 등이 있다 — 저장소 밖에 둔다)
- [ ] **키 3종**을 갖고 있다
  - 카카오 **REST API 키** (로그인 + 장소 검색용)
  - 카카오 **JavaScript 키** (지도 그리기용)
  - **엘리스 ML API 키** (AI가 사유를 읽을 때 쓴다)
- [ ] **카카오 계정 2~3개** (사람 역할을 할 계정. 한 명이 여러 창에서 서로 다른 계정으로 로그인한다)
- [ ] 브라우저 2종 또는 **일반 창 + 시크릿 창** (계정을 나눠 로그인하려면 필요하다)

> 💡 키는 **절대 채팅이나 깃에 올리지 마세요.** 아래에서 말하는 `.env` 파일에만 넣습니다. 이 파일은 깃이 자동으로 무시합니다.

---

## 2. 한 번만 하는 준비

### 2-1. 카카오 개발자 콘솔 설정 (https://developers.kakao.com)

내 애플리케이션을 열고 아래 3가지를 합니다.

1. **카카오 로그인**을 켠다(활성화 ON).
2. **Redirect URI**에 아래 주소를 **글자 하나 틀리지 않고** 등록한다.
   ```
   http://localhost:8000/auth/kakao/callback
   ```
3. **플랫폼 → Web** 에 아래 주소를 등록한다 (지도가 뜨려면 필요).
   ```
   http://localhost:5173
   ```

그리고 **앱 키** 화면에서 두 가지를 메모해 둡니다.
- **REST API 키** → 아래 `KAKAO_CLIENT_ID`에 넣는다.
- **JavaScript 키** → 아래 `VITE_KAKAO_MAP_KEY`에 넣는다.

> ❗ 카카오 앱 설정에서 **"Client Secret"을 켜 두었다면**, 그 값도 `KAKAO_CLIENT_SECRET`에 넣어야 합니다. 꺼 두었으면 비워 둡니다.

### 2-2. 백엔드(서버) 설정

터미널을 열고 저장소 안의 `backend` 폴더로 이동합니다.

```bash
cd backend
```

**① 파이썬 부품 설치** (처음 한 번)
```bash
pip install -r requirements.txt
```

**② 설정 파일 만들기** — `backend/.env.example` 을 복사해서 `backend/.env` 로 이름을 바꿉니다. 그다음 `.env` 를 메모장으로 열어서 **아래 값만** 이렇게 고칩니다. (나머지는 그대로 둡니다.)

| 줄 | 이렇게 적기 | 설명 |
|---|---|---|
| `PINGO_ENV=` | `dev` | **꼭 적기.** 안 적으면 서버가 안 켜진다 |
| `PLACES_MODE=` | `real` | 진짜 장소 검색을 쓴다 (`dev`면 가짜 5곳만 나온다) |
| `LLM_MODE=` | `real` | 진짜 AI를 쓴다 (`dev`면 AI가 사유를 읽지 못한다) |
| `KAKAO_CLIENT_ID=` | 카카오 **REST API 키** | **`=` 바로 뒤에 붙여서** 적는다. 공백이나 따옴표를 넣지 않는다 |
| `KAKAO_CLIENT_SECRET=` | (Client Secret을 켰을 때만) | 안 켰으면 줄을 비운다 |
| `KAKAO_REDIRECT_URI=` | `http://localhost:8000/auth/kakao/callback` | 2-1에서 등록한 것과 똑같이 |
| `ELICE_ML_API_BASE_URL=` | 엘리스에서 받은 주소 | 키를 새로 받아도 보통 그대로다 |
| `ELICE_ML_API_KEY=` | 엘리스 키 | 새로 받은 키 (옛 키는 만료돼서 `401`이 난다) |

`.env` 안에 `AUTH_MODE=` 로 시작하는 줄이 있으면 **지워도 됩니다**(더 이상 쓰지 않는 설정).

**③ 데이터베이스 켜기** (Docker Desktop 프로그램이 켜져 있어야 한다)
```bash
docker compose up -d
```
> 줄이 몇 개 나오고 `Started` 라고 끝나면 성공입니다. 처음엔 이미지를 받느라 1~2분 걸립니다.

**④ 데이터베이스에 표(테이블) 만들기**
```bash
python -m alembic upgrade head
```
> 마지막에 `Running upgrade ... 0020_evidence_wants` 같은 글이 나오면 성공입니다.

**⑤ 가게 데이터 넣기** (약 5분, **딱 한 번**만. 아래 `<데이터폴더>` 는 실제 폴더 경로로 바꿉니다)
```bash
python -m places.load restaurants --file "<데이터폴더>/restaurant_seoul_curated.csv" --labels "<데이터폴더>/restaurant_seoul_curated_labels.json"
python -m places.load cafes --file "<데이터폴더>/cafe_seoul_curated.csv" --labels "<데이터폴더>/cafe_seoul_curated_labels.csv"
```
> ✅ 성공하면 `DB: 신규 11843` (음식점), `DB: 신규 533` (카페) 같은 줄이 나옵니다. 좌표가 없는 가게는 자동으로 건너뛰니 숫자가 데이터 파일보다 조금 적은 게 정상입니다.
> 💡 먼저 연습으로 해보고 싶으면 명령 맨 끝에 `--dry-run` 을 붙이세요. 실제로는 넣지 않고 결과만 보여 줍니다.

### 2-3. 프론트(화면) 설정

새 터미널을 열고 저장소의 `frontend` 폴더로 갑니다.

```bash
cd frontend
npm install
```

`frontend` 폴더 안에 **`.env.local`** 이라는 파일을 새로 만들고 아래 두 줄을 넣습니다. (키는 본인 것으로)
```
VITE_API_BASE_URL=http://localhost:8000
VITE_KAKAO_MAP_KEY=여기에_카카오_JavaScript_키
```
> `VITE_API_BASE_URL` 을 적으면 "연습용 가짜 서버"가 꺼지고 **진짜 서버**에 붙습니다. 이 줄이 없으면 화면은 뜨지만 진짜 데이터가 아니에요.

---

## 3. 시연할 때마다 켜는 순서

터미널 **2개**를 씁니다.

**터미널 ① 서버**
```bash
cd backend
docker compose up -d
python -m uvicorn main:asgi_app --port 8000
```
> ✅ `Application startup complete.` 라고 나오면 켜진 것입니다. **이 창은 시연이 끝날 때까지 닫지 마세요.**
> 확인: 브라우저에서 `http://localhost:8000/health` 를 열면 `{"status":"ok"}` 가 보입니다.

**터미널 ② 화면**
```bash
cd frontend
npm run dev
```
> ✅ `Local: http://localhost:5173/` 라고 나오면 됩니다. 브라우저에서 이 주소를 엽니다.

> ⚠️ 주소는 꼭 **`localhost`** 로만 쓰세요. `127.0.0.1` 로 열면 로그인이 풀려 버립니다(쿠키가 안 붙음).

## 4. 시연 대본

세 사람 역할을 정합니다. (사람이 적으면 2명도 되고, 한 사람이 창을 나눠 써도 됩니다.)

| 역할 | 이름(예시) | 브라우저 |
|---|---|---|
| **A 방장** | 지우 | 일반 창 |
| **B 구성원** | 서연 | 시크릿 창 |
| **C 구성원** | 민재 | 다른 브라우저(또는 두 번째 시크릿 창) |

> 💡 시크릿 창은 서로 쿠키를 나누지 않아서, 계정이 섞이지 않습니다.

### 장면 1 — 로그인하고 지도 만들기 (A)

1. `http://localhost:5173` 을 연다 → **「카카오로 시작하기」** 를 누른다.
2. 카카오 로그인 화면에서 A 계정으로 로그인 → 동의한다.
3. **「새 지도 만들기」**: 제목 `성수 팀 시연`, 기간(예: 11월 1일~2일)을 넣고 **「지도 만들기」** 를 누른다.
   - ✅ 지도 화면이 열리고 아래에 탭 3개가 보입니다: **마킹된 장소 / AI 추천 / 확정된 장소**

### 장면 2 — 친구 초대하기 (A → B, C)

1. 화면 위쪽의 **지도 정보(구성원 아이콘)** 를 열고 **「초대 링크 공유하기」** 를 눌러 링크를 **복사**한다.
2. B 창, C 창에서 그 링크를 연다 → 로그인(각자 계정) → **「참여하기」**.
   - ✅ A 화면의 구성원 목록에 3명이 보이고, A에게 **방장** 표시가 붙어 있습니다.

### 장면 3 — 핀 찍기 (모두)

검색창에 **가게 이름을 그대로** 쓰고(엔터), 나온 결과에서 **「핀 찍기」**를 누릅니다.

| 누가 | 검색창에 쓸 말 | 결과 |
|---|---|---|
| A | `기왕생고기` | 기왕생고기 |
| B | `텐바` | 텐바 |
| C | `용용선생 마라도원` | 용용선생 마라도원 |
| A | `성수노루` | 성수노루 |
| B | `라이홍` | 라이홍 |

> ⚠️ **`성수 삼겹살` 같은 음식 이름으로 검색하면 안 됩니다.** 새 지도는 서울 중심에서 시작하고 검색 결과는 지도 중심에서 가까운 순이라, 성수가 아닌 가게가 먼저 나오고 대본의 가게는 10곳 안에 없습니다(점검에서 확인). **위 표처럼 가게 이름 그대로 검색**하면 결과가 1곳으로 나오고 지도가 성수로 이동합니다.

- ✅ 한 사람이 핀을 찍으면 **다른 창에도 몇 초 안에 저절로** 핀이 나타납니다(새로고침 필요 없음).
- ✅ 지도 아래 **마킹된 장소** 탭에 5곳이 목록으로 보입니다.

> ⚠️ **검색 결과 중에는 "아직 지원하지 않는 장소예요"로 흐리게 나오는 가게가 많습니다**(음식 이름으로 검색한 결과의 약 9할). 우리 데이터에 없는 가게라서 핀을 못 만듭니다. 정상이니까 놀라지 마세요. 위 표의 가게는 항상 됩니다.
> 같은 가게를 두 번 찍으면 "이미 지도에 있는 장소예요"가 나옵니다. 이것도 정상입니다.

### 장면 4 — 의견 남기기 (모두)

핀을 눌러 열고, 반응을 고릅니다. (♥ = 좋아요, 🚫 = 반대)

| 누가 | 어느 핀 | 반응 | 내용 |
|---|---|---|---|
| A | 기왕생고기 | ♥ | (그냥 누르면 됨) |
| B | 텐바 | ♥ | (그냥 누르면 됨) |
| C | 용용선생 마라도원 | 🚫 | **사유 칩에서 「매워요」 선택** |
| A | 성수노루 | ♥ | 사유에 `조금 느끼한 것 같아요` 라고 써도 됩니다(사유는 선택) |

- ✅ **🚫 반대는 사유 없이는 등록되지 않습니다.** (칩이나 글 중 하나는 꼭 있어야 해요 — 이게 핀고의 규칙이에요.)
- ✅ 다른 창에서 **"○○님이 반대 의견을 남겼어요"** 알림이 뜹니다.
- ✅ 마킹된 장소 위쪽에 **"3/3명이 의견을 남겼어요"** 같은 문구가 보입니다.

> 🚫 **갑각류 알러지 칩(「갑각류 알러지가 있어요」)은 시연에서 누르지 마세요.** 우리 데이터에는 "갑각류가 없다"고 확인된 가게가 하나도 없어서, 이 칩을 쓰면 안전을 위해 **모든 가게가 빠지고 추천이 0곳**이 됩니다. (안전 규칙이 정상 작동한 것이지만 시연에는 어색합니다.) 대신 **「매워요」 칩**이 가장 보기 좋습니다.

### 장면 5 — AI 추천 받기 (A만)

1. 아래 **AI 추천** 탭을 누른다. 카테고리는 **음식점**.
   - 그 카테고리에 ♥ 또는 🚫 의견이 달린 핀이 하나도 없으면 "**의견이 모여야 추천이 열려요**"라고 나옵니다. 핀 하나에라도 의견이 있으면 열리고, **혼자 쓰는 지도도 똑같습니다**(2026-10-07 변경).
2. 추천을 시작한다. → AI가 사람들의 사유를 읽는 동안 **5~10초** 기다린다.
3. **"이 조건으로 추천해도 될까요?"** (근거 확인) 화면이 나온다. 이게 핵심입니다.
   - ✅ 「**매운맛 전문 제외**」 (민재의 "매워요")
   - ✅ 「**기름진 메뉴 위주 제외**」 (지우의 "조금 느끼한 것 같아요")
   - ✅ 「#가격대 제외」 (민재의 "가격이 조금 부담돼요" — 가격은 지금 걸러 내지 않고 표시만 합니다)
   - 이렇게 **AI가 사람 말을 조건으로 바꿔 보여 줍니다.** 틀렸다면 줄 옆의 **−** 버튼으로 뺄 수 있어요. 직접 쓰고 싶으면 **+** 로 추가합니다(**「근거 고치기」**).
   - ⚠️ **드물게(점검 8번 중 1번) AI가 조건으로 정리하지 못하고 말 그대로("매워요"만) 보여 줄 때가 있습니다.** 「제외」 글자가 안 붙어 있으면 **「취소」를 누르고 다시 「추천받기」**를 눌러 보세요(두 번째에는 정리됐습니다).
4. **「네, 추천해주세요」** 를 누르고, 이어서 나오는 **지역(검색할 동네 원) 확인**을 그대로 확인해 실행한다.
5. **결과**: 추천 가게가 **3곳** 나온다. (예: `맛보래`, `부산밀면`, `주식회사 식당컴퍼니 소바식당` — 컴퓨터 상태에 따라 가게는 달라질 수 있습니다.)
   - ✅ 각 가게마다 **추천 이유**, **조건 체크 칩**(「기름진 메뉴 위주 아님」「매운맛 전문점 아님」「한식」 등 — 「영업 여부 확인 필요」는 아직 확인하지 못했다는 뜻), **"2명 중 2명 충족"** 같은 충족 표시, **출처**가 붙어 있습니다.
   - ✅ **B, C의 화면에는 아직 추천 가게가 보이지 않습니다.** AI 추천은 요청한 사람(A)에게만 보이고, A가 **「지도에 올리기」**를 눌러야 모두에게 공개됩니다. 이것이 핀고의 첫 번째 약속입니다.
6. 마음에 드는 가게 하나에서 **「지도에 올리기」** 를 누른다.
   - ✅ B, C 화면에도 그 핀이 **점선 모양**(AI 추천)으로 나타나고, 추천 이유가 그대로 남아 있습니다.

> 💡 **여러 번 해볼 수 있어요.** 결과가 마음에 안 들면 **반경 넓히기**(동네를 더 넓게), **다시 추천**을 눌러 보세요.
> ⚠️ **추천 횟수는 한 사람당 5번**이고 「추천받기」·「다시 추천」을 모두 합쳐서 셉니다(화면에 「N번 남음」으로 보입니다). **리허설에서 많이 써 버리면 시연에서 못 씁니다.** 리허설은 지도를 새로 만들고, 시연은 아직 안 쓴 계정으로 하세요.

### 장면 6 — 확정 리스트와 동선 (A)

1. 가고 싶은 핀을 열어 **「★ 확정 리스트에 넣기」** 를 누른다. (3곳 정도)
2. **확정된 장소** 탭에서 목록을 끌어서 **순서를 바꿔 본다**. (밀어서 빼기도 된다)
3. 확정된 곳이 **2곳 이상**이면 **「동선 보기」** 를 누른다.
   - ✅ 가까운 순서로 방문 순서와 걸리는 시간이 나옵니다. (순서만 알려 줍니다. "몇 시에 어디"는 만들지 않아요 — 핀고는 일정 자동 생성을 하지 않습니다.)

**시연 끝!** 이 흐름이 핀고의 핵심 약속을 모두 보여 줍니다.

> 💬 시연하면서 이렇게 설명하면 좋아요.
> - "AI는 지도를 마음대로 바꾸지 않아요. 제안은 나한테만 보이고, 내가 올려야 모두에게 보여요."
> - "안 맞는 가게는 **AI가 아니라 코드가** 걸러요. AI는 사람 말을 조건으로 바꾸는 일만 해요."
> - "아니라고 확인된 가게만 남기고, **모르는 가게는 안전을 위해 빼요.**"

## 5. 문제가 생기면

| 이런 일이 생겼다 | 왜 그럴까 | 이렇게 해 보세요 |
|---|---|---|
| 서버가 안 켜지고 `ConfigError` 가 뜬다 | `.env` 에 `PINGO_ENV=dev` 가 없다 | `backend/.env` 에 `PINGO_ENV=dev` 를 적고 다시 켠다 |
| `relation "..." does not exist` | 표를 아직 안 만들었다 | `python -m alembic upgrade head` |
| 로그인 버튼을 누르면 카카오에서 **KOE006** 오류 | Redirect URI가 콘솔과 `.env` 에서 다르다 | 둘이 `http://localhost:8000/auth/kakao/callback` 으로 **글자까지 똑같은지** 확인 |
| 카카오 로그인 후 계속 로그인 화면으로 돌아온다 | 주소를 `127.0.0.1` 로 열었다 | 주소를 `http://localhost:5173` 으로 연다 |
| 로그인 도중 **"로그인을 취소했어요"** 같은 안내가 뜬다 | 카카오 화면에서 취소를 눌렀다 | 다시 로그인 버튼을 누른다 |
| 지도가 안 보이고 회색이다 | 지도 키가 없거나 도메인 미등록 | `frontend/.env.local` 의 `VITE_KAKAO_MAP_KEY` 와 카카오 콘솔의 Web 도메인(`http://localhost:5173`) 확인 후 `npm run dev` 를 껐다 켠다 |
| 검색하면 "장소 검색을 지금은 쓸 수 없어요" | 카카오 REST 키가 없거나 틀리다 | `.env` 의 `KAKAO_CLIENT_ID` (앞에 공백이 없는지), `PLACES_MODE=real` 확인 후 서버를 껐다 켠다 |
| 검색 결과가 전부 흐리다 | 그 가게들이 우리 데이터에 없다 | 위 표(장면 3)의 가게로 다시 검색해 본다 |
| 추천 받기가 **실패했어요** | AI 키가 만료되었거나 틀렸다 | `ELICE_ML_API_KEY` 를 새 키로 바꾸고 서버를 껐다 켠다. 서버 창에 `401` 이 보이면 키 문제다 |
| 추천이 **0곳**이다 | 안전 조건 때문에 후보가 다 빠졌다(특히 갑각류 칩) | 갑각류 대신 **「매워요」** 칩을 쓰거나 **반경 넓히기**를 눌러 본다 |
| 추천이 계속 안 켜진다("의견이 모여야 추천이 열려요") | 그 카테고리(음식점)에 ♥/🚫 의견이 달린 핀이 하나도 없다 | 음식점 핀 하나에 ♥나 🚫를 남긴다 |
| 핀이 **다른 창에 안 나타난다** | 실시간 연결이 끊겼다 | 화면의 **「다시 연결」** 버튼을 누르거나 새로고침(F5) |
| 아예 처음부터 다시 하고 싶다 | — | **새 지도를 만들면** 됩니다. 이전 지도는 그대로 둬도 아무 문제 없어요 |

> 💡 서버 창(터미널 ①)에 나오는 빨간 글자는 대부분 원인이 적혀 있어요. 막히면 그 글자를 개발자에게 그대로 보여 주세요.

## 6. 알아 두면 좋은 것 (시연 전에 한 번 읽기)

- **가게는 서울 음식점·카페만** 있습니다. 관광지는 추천 후보가 없어서, 시연에서는 음식점만 하세요.
- **핀은 한 동네에 모아서** 찍으세요(예: 성수). 서로 멀리 떨어진 가게들(성수와 홍대)만 있으면 둘 사이 빈 땅을 기준으로 찾아서 추천이 비어 보여요. 알려진 한계입니다(#226).
- **AI 추천이 5~10초 걸리는 건 정상**입니다(AI가 사람 말을 읽는 시간). 사유가 아주 많으면 20초까지 걸릴 수 있습니다.
- **알러지·매운맛·기름짐 같은 안전 조건**은 ♥든 🚫든, 어느 반응에 적었든 **"싫다"는 뜻이면 그 가게를 뺍니다.** 그리고 확인되지 않은 가게도 뺍니다(안전이 먼저).
- AI가 사람 말을 잘못 읽었을 수 있으니, 항상 **근거 확인 화면**에서 사람이 확인하고 **−** 로 뺄 수 있게 만든 것이 핀고의 방식입니다.
- 이 시연은 **내 컴퓨터에서만** 열립니다. 다른 사람이 인터넷으로 접속할 수는 없습니다.

## 7. 끝낼 때

- 터미널 ①, ② 에서 `Ctrl + C` 를 눌러 서버와 화면을 끈다.
- 데이터베이스를 끄려면 `backend` 폴더에서 `docker compose stop` (데이터는 그대로 남습니다. 다음에 `docker compose up -d` 로 다시 켜면 됩니다).
- ⚠️ **`docker compose down -v` 는 쓰지 마세요.** 데이터가 전부 지워져서 2-2의 ⑤를 다시 해야 합니다.
