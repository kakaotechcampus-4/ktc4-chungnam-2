# 에러 코드 카탈로그

공통 포맷(`api-spec.yaml`의 `Error` 스키마): `{ code, message, detail }`
각 코드는 최종기획안 6절 "함께 만든 화면"과 1:1로 매핑되도록 만들었다 — 프론트가 이 표만 보고 8개 화면을 전부 먼저 만들 수 있다.

| code | HTTP | 발생 상황 | 대응 화면 (6절) |
|---|---|---|---|
| `MAP_EMPTY` | 200(빈 배열) | 핀이 하나도 없음 | "아직 아무도 핀을 찍지 않았어요" + 입력 경로 3개 |
| `NO_RESULTS` | 404 | 필터 통과 후보 0개(**이전에 올린 후보까지 합쳐 하나도 없을 때만** — 게시 후보가 남아 있으면 200 + `new_count: 0`, #845) | "필터에 걸리는 핀이 없어요" / 어느 조건이 몇 곳 걸렀는지(`detail.funnel`) + 이번에 쓴 근거(`detail.applied_evidence`·`detail.no_applied_conditions`, #845) + 반경넓히기/근거고치기/직접찍기 + 카카오맵에서 더 찾아보기(`detail.external_search`, #798) |
| `NOT_READY` | 409 | 추천 준비 미달 — 그 카테고리에 ♥/🚫 의견이 달린 핀이 없음(2026-10-07, #360) | "의견 핀 0곳 · 1곳 더 필요" |
| `REQUEST_IN_PROGRESS` | 409 | 같은 `Idempotency-Key`의 첫 요청이 아직 처리 중(`POST /maps/{mapId}/runs`, 모델 대기, #811) | 진행 표시를 유지하고 잠시 뒤 같은 키로 다시 보낸다 |
| `EVIDENCE_REQUIRED` | 422 | 반대 반응에 사유 없음 | 등록 버튼 비활성화 (가드레일 3) |
| `EVIDENCE_LIMIT` | 409 | 근거 확인 화면에서 「+」로 직접 추가한 글이 run 하나에 10개를 넘음(뺀 것 포함, #707). 글 하나에 조건이 여럿이어서 근거 줄이 여럿 생겨도 글 1개로 센다. `detail`에 `{ limit, used }`(글 수). 한 요청에 글 5개 초과는 422 `VALIDATION_ERROR` | "직접 추가는 10개까지예요" + 「+」 비활성 |
| `PIN_DUPLICATE` | 409 | 이미 지도에 있는 장소 | 중복 핀 안내 UI |
| `AI_PIN_PRIVATE` | 404 | 「지도에 올리기」(`POST /candidates/{id}/publish`) 전용. 구성원이어도 요청자가 아닌 사람이 남의 후보를 게시하려 할 때, 후보의 존재를 숨기려고 404로 답한다. 핀 API는 이 코드를 내지 않는다(v1은 private 핀이 없다) | "비공개 AI 핀 접근 시 안내" |
| `REGION_CONFLICT` | 409 | 반경 사유끼리 안 겹침 | "두 조건을 동시에 만족하는 곳이 없어요" 확인창 (5-6-1) |
| `RETRY_LIMIT` | 429 | 재시도 상한 초과 — 지도 안에서 구성원 각자 10회, 카테고리·run 무관(요청자·지도 단위) (#31, 2026-10-15 5→10회 상향) — **상한을 다 쓴 요청자의 근거 수정(`PATCH /runs/{id}/evidence`, `×`·`＋`)도 같은 코드로 거절한다**(#845, 모델을 부르기 전에) | "10번까지만 찾습니다" (FE는 `detail.attempt_limit`으로 숫자를 그린다) |
| `WIDEN_LIMIT` | 409 | 반경 넓히기가 이미 상한(기본값 원 도보 30분) | "더 넓히면 여행지를 벗어나요" + 근거 고치기/직접 찍기 |
| `REACTION_NOT_ALLOWED` | 422 | 숙소 핀에 반응 요청 (#154) | 숙소 핀엔 반응 UI를 애초에 그리지 않음 — 보이면 FE 버그 신호 |
| `INVITE_NOT_FOUND` | 404 | 없거나 잘못된 초대 토큰. 삭제된 지도의 토큰도 여기에 해당한다(#369) | "유효하지 않은 초대 링크예요" |
| `MAP_LIMIT` | 409 | 내 지도가 이미 20개인데(#433에서 10→20) 지도를 만들거나 초대를 수락함. 만들거나 참여한 지도를 합산하고, 삭제된 지도와 나간 지도는 세지 않는다. `detail`에 `{ limit, count }`(#369) | "지도는 10개까지 만들거나 참여할 수 있어요" + 나가기·삭제 안내 |
| `OWNER_CANNOT_LEAVE` | 409 | 넘길 사람이 없는 방장의 나가기 요청(혼자이거나 남은 사람이 전부 탈퇴자, #369) | 나가기 대신 「지도 삭제」를 안내 |
| `LINK_NOT_SUPPORTED` | 422 | 지도 링크 해석(`POST /places/from-link`)에서 허용 호스트가 아니거나 형식을 모름 — 네이버·인스타·블로그 링크 포함(#474) | "구글맵·카카오맵 링크만 붙일 수 있어요" |
| `LINK_UNRESOLVED` | 422 | 단축 링크를 열지 못했거나 링크에서 장소를 찾지 못함(#474) | "링크에서 장소를 찾지 못했어요. 검색으로 남겨 주세요" |
| `RUN_NOT_FINISHED` | 409 | 아직 끝나지 않았거나 실패한 run의 결과 조회(`GET /runs/{runId}/result`, #469) | 진행 중이면 진행 화면, 실패면 「다시 추천받기」 |
| `SUGGESTION_RESOLVED` | 409 | 이미 수락, 닫기, 만료, 무효화된 지도 제안을 수락하거나 닫음(v2 계획 보조 에이전트, #510). 다른 구성원이 먼저 처리한 경우 | 에이전트 상태(`GET /maps/{mapId}/agent`)를 다시 받아 바텀시트를 갱신 |
| `INVITE_REVOKED` | 410 | 방장이 끈 초대 토큰(#467). 요약 조회·수락에서 난다 | "방장이 이 초대 링크를 껐어요. 새 링크를 요청하세요" |
| `OWNER_TARGET_INVALID` | 422 | 방장을 넘길 수 없는 대상 — 지금 구성원이 아니거나 탈퇴했거나 나 자신(#468) | 구성원 목록을 다시 불러와 고르게 한다 |
| `GUEST_NOT_ALLOWED` | 403 | 게스트(이름만 입력한 임시 계정, #472)가 못 하는 일 — 지도 만들기. 구성원 행동은 막지 않는다 | "지도를 만들려면 카카오로 로그인해 주세요" |
| `GUEST_LIMIT` | 409 | 한 초대 링크로 만들 수 있는 게스트 수(10)를 넘음(#472) | "이 링크로는 더 입장할 수 없어요. 초대한 분께 새 링크를 요청하세요" |
| `INVITE_EXPIRED` | 410 | 만료된 초대 토큰 | "초대 링크가 만료됐어요. 초대한 분께 새 링크를 요청하세요" |
| `PLACE_NOT_SUPPORTED` | 422 | `source: search`인데 검색 결과와 짝이 되는 자체 DB 장소가 없음 (핀 만들기, #191) | "장소 정보가 없는 핀이에요" — 「그래도 핀 남기기」(`source: live`, #382)로 다시 보낸다 |
| `COURSE_NOT_ENOUGH_PLACES` | 422 | AI 코스 짜기(`POST /maps/{mapId}/courses`, #334)에서 코스를 짤 확정 장소가 2곳 미만. 좌표를 알 수 없는 실시간 핀은 세지 않는다. `detail`에 `{ min, count }` | 「AI 코스 짜기」 버튼 비활성화 + "확정 리스트에 장소를 2곳 이상 담아 주세요" |
| `COURSE_LIMIT` | 429 | 사용자당 하루(KST 자정 초기화) 코스 요청 5회 초과. `detail`에 `{ limit, used }` | "오늘은 5번까지 코스를 짤 수 있어요" |
| `COURSE_IN_PROGRESS` | 409 | 같은 지도에서 내가 요청한 코스를 아직 짜는 중. `detail`에 `{ course_run_id }` | 진행 화면(`GET /course-runs/{runId}`)으로 이동 |
| `RATE_LIMITED` | 429 | 사용자당 호출 상한 초과(현재 장소 검색, #180) | "너무 빨리 검색하고 있어요. 잠시 뒤 다시 시도해 주세요" |
| `PLACES_UNAVAILABLE` | 503 | 지도 API 검색이 전부 실패(키 없음·장애·호출 상한, #180) | "지금은 장소를 검색할 수 없어요. 잠시 뒤 다시 시도해 주세요" / 좌표로 찍기는 계속 가능 |
| `RECOMMEND_FAILED` | 500 | 추천 파이프라인 실패 | "조건이 까다로워서가 아니에요" + "남긴 것은 그대로 있어요" |
| `SHORTLIST_CATEGORY_EMPTY` | 200(빈 배열) | 확정 분류에 항목 없음 | "이 분류에는 확정된 곳이 없어요" |
| `UNAUTHORIZED` | 401 | 인증 실패 | 전역 인터셉터 + next 파라미터 리다이렉트 |
| `FORBIDDEN` | 403 | 권한 없는 액션 (permissions.md 범위 밖) | 해당 버튼이 애초에 disabled여야 함 — 403이 보이면 FE 버그 신호 |
| `IDEMPOTENCY_CONFLICT` | 409 | 동일 Idempotency-Key로 다른 바디 요청 | 재시도 로직 버그 신호. 첫 적용처는 `POST /maps/{mapId}/runs`(#811, #48) |
| `VALIDATION_ERROR` | 422 | 요청 형식·필수값 오류 | 폼 필드 오류 표시 — FE 버그 신호 |
| `NOT_FOUND` | 404 | 없는 경로·없는 리소스 | 전역 404 |
| `INTERNAL_ERROR` | 500 | 미처리 서버 예외 | 전역 에러 화면 |

마지막 3행(`VALIDATION_ERROR`·`NOT_FOUND`·`INTERNAL_ERROR`)은 화면 상태가 아니라 **봉투 통일용**이다 — 이게 없으면 FastAPI 기본 응답이 그대로 나가서 FE가 에러 형태를 두 가지로 파싱해야 한다(`backend/common/errors.py`, PR #49).

## 규칙

- 위 표에 없는 신규 화면 상태가 필요해지면 **먼저 코드를 여기 추가**하고 나서 구현한다 — 화면이 코드보다 먼저 생기면 FE·BE가 각자 다른 이름을 붙이게 된다.
- `detail`에는 화면이 바로 쓸 수 있는 구조화 값을 넣는다. 예: `NO_RESULTS`의 `detail.funnel`, `RETRY_LIMIT`의 `detail.attempt_no`·`detail.attempt_limit`.
